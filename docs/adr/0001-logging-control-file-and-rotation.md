# 日誌控制檔、雙 sink 等級與輪替

## Status

accepted

## 決策

掃描器（GUI 與 CLI）共用一套 logging 設定：控制檔固定放在
`%LOCALAPPDATA%\FireWallExcelFinder\logging.ini`，首次啟動自動建立，只包含
`ui` 與 `file` 兩個等級（預設 `WARNING` / `INFO`）。日誌檔固定為
`%LOCALAPPDATA%\FireWallExcelFinder\logs\firewall_excel_finder.log`，以 UTF-8
附加寫入，單檔上限 5 MiB、保留 3 個舊檔。GUI 的日誌面板與 CLI 的 console
共用 `ui` 等級；檔案 sink 使用 `file` 等級。控制檔在程式啟動時讀取一次，
格式或等級錯誤一律退回預設值，不讓程式啟動失敗。

選擇使用者可寫的 `%LOCALAPPDATA%` 而非專案目錄，是因為程式可能安裝在唯讀
路徑，且日誌與控制檔都屬於「這位使用者在這台機器上」的狀態；把 UI 與檔案
等級分開，則是因為兩者的讀者與保存期限不同：GUI 面板給當下除錯，檔案給事後
追查。

## 考慮過的選項

- **控制檔放專案根目錄**：可隨 repo 版控，但程式安裝在唯讀路徑時無法自動
  建立，且不同使用者會共用同一份設定。
- **單一等級同時控制 UI 與檔案**：設定較簡單，但無法「UI 安靜、檔案詳細」，
  而這正是需求的核心。
- **每個程序各自一個日誌檔**：可避開多程序輪替競爭，但會讓「日誌檔在哪」變得
  不可預期。
- **JSON 控制檔**：結構清楚，但需要額外處理註解與預設值說明；INI 用
  `configparser` 即可，且可直接寫註解。

## 影響

- 控制檔與日誌路徑屬於使用者可見契約；日後搬移位置需要遷移或相容讀取。
- 同時開啟多個 CLI/GUI 實例時，`RotatingFileHandler` 不是多程序安全的；可能
  遺失少量訊息或產生非預期輪替，這是已知且接受的限制。
- GUI 的「警告」分頁仍顯示掃描結果 warnings，**不受** `ui` 等級過濾；只有
  「日誌」分頁受控。
- 日誌不記錄儲存格完整文字與目標規則原始行，避免敏感內容長期落盤。
- 日誌目錄或檔案無法建立時，停用檔案 sink 並在 UI 留下 ERROR，程式其餘功能
  照常運作。
